---
title: MCP servers and connections
description: Discover accessible MCP servers and manage account or team connections.
---

All endpoints use Developer API bearer authentication. `mcp:read` is required for GET requests and `mcp:write` for POST, PATCH, and DELETE requests. OAuth access tokens must be granted the corresponding scopes.

## Server catalog

| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/mcp/servers/` | List public and workspace-owned servers |
| GET | `/v1/mcp/servers/{server_id}/` | Retrieve an accessible server |

## Connections

| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/mcp/connections/` | List connections owned by the API key's account or team |
| POST | `/v1/mcp/connections/` | Create an account/team connection |
| GET | `/v1/mcp/connections/{connection_id}/` | Retrieve a connection |
| PATCH | `/v1/mcp/connections/{connection_id}/` | Update label, enabled state, or credentials |
| DELETE | `/v1/mcp/connections/{connection_id}/` | Delete a connection |
| POST | `/v1/mcp/connections/{connection_id}/oauth/initiate/` | Begin OAuth authorization for a connection |

Create an API-key-authenticated connection:

```json
{
  "server_id": 12,
  "label": "calendar",
  "credentials": { "api_key": "..." }
}
```

Use `bearer_token` for bearer authentication, `basic_username` and `basic_password` for Basic authentication, and `{}` for no-auth servers. OAuth credentials cannot be supplied directly; create the connection without credentials and use the OAuth initiate endpoint, then redirect the user to `authorization_url`.

Secret values are write-only. Connection responses include `has_credentials` and `credential_summary`, never the stored API key, password, or OAuth token. MCP request usage logs retain credential field names only, not their values.
